# G1 — BOT1-A Browser-Input Evidence Gate
**Mode:** Convergence/Instrumentation — no new gameplay.

## Purpose
Distinguish input confusion, targeting failure, movement obstruction, physical/chemical acceptance, false HUD state, and genuine Host causality in player-style runs. This is an evidence gate, not a new region, quest or ability.

## Allowed scope
New external browser input runner, read-only source-contract validation, REC1 capture, screenshots, isolated report analyzer. Findings can propose future targeted patches but no gameplay changes are shipped in BOT1-A.

## Locked
InputSystem and ControlMap; Core phase debug O; material ledger identity/conservation; Silt grip/seat/contact semantics; C0D Host receipts; LS1E1/E2 provenance; C0E2-B coupling; C0E3 waves; LANG1 vocabulary if installed; camera/visual/audio baselines (HC027D1 volume). Do not rewrite source or jump debug platforms during acceptance runs.

## Required evidence
- First minute: unmodified input path + HUD + REC1 + captured visual frame.
- Target interaction: separate request → candidate/eligibility → accepted/rejected owner response → retained consequence. The recorder may not yet prove every stage; mark gap **UNEXERCISED**.
- Out-of-range target: no invented acceptance or false success.
- Movement: commanded movement, cell transitions, side volume, boundary pressure, stalled intervals, recovery; do not infer physical walls from one sample.
- Full circuit: only unique parent sequence / accepted material events count. No cross-region matter arrival without matter authority.
- 3/6/12: no debug forced phase interpreted as physiological resolution.

## BOT1-A acceptance versus full G1
BOT1-A can be accepted as an **instrumented input harness** when it runs on the actual game, exports REC1 for all three profiles, preserves no-state-write rule, and yields owner-grounded report fields.

Full G1 requires ≥3 seeds × 3 policies, zero invented receipts or false HUD completion, repeatability analysis (not assumed deterministic by seeded input), one ≥90s successful first slice, one unassisted route attempt, and human or image-capable review of actual frames. BOT1-A alone does **not** finish G1: it has no 3D visual understanding and doesn't guarantee an objective-solving agent.

## Follow-up hierarchy
G1 BOT1-A browser input diagnostics → G1 BOT1-B visual/goal-directed navigator → G2 ability/target acceptance lock → G3 physical/tissue visual response → G4 genuine 3/6/12 physiological rules → G5 Host full authenticated loop → G6 integrated slice. Do not skip G1 by adding another feature.
