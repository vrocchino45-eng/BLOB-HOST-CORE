## 01. Current Thesis

BLOB: HOST CORE is a cinematic chemistry-driven growth-exploration game where the player awakens as a small becoming-core inside the living interior of a greater Host Core, learns through nutrients, entities, orbiters, thresholds, chemistry, and risk, grows toward host-capable responsibility, and eventually discovers a larger ecology of Hosts, collapse, reseeding, and the Beyond.

The player does not conquer the world. The player becomes legible to it.

The core promise is that the player will experience the laws of existence through movement, transformation, ecology, polarity, resonance, scale, inversion, and discovery rather than through exposition.

---

## 02. True World Model

The world is nested:

```text
The Beyond / Ethereal Field
  -> Core Clouds / Becoming Fields
  -> Host Cores
  -> Host Anatomy / Interior Systems
  -> Regions, Chambers, Routes, Thresholds
  -> Nutrients, Materials, Entities, Orbiters, Relics
  -> Player Core Growth
  -> Player becomes host-capable
  -> Player understands the ecosystem of Hosts
```

The opening micro-world is not a random tutorial. It is the interior working system of a larger Host Core. Surface Wake, Guide Threshold, Hub Chamber, Vascular Route, Graveyard, Comb Threshold, and Aperture Fields are living organs, route tissues, memory chambers, reproductive/growth structures, and threshold systems inside or around a Host Core.

---

## 03. Host Core Cosmology

A Host Core is a large living world-being. It is not simply a planet, organism, god, or dungeon. It is a living core-system capable of growing interior worlds, sustaining micro-ecologies, producing nutrients and materials, forming routes and thresholds, hosting orbiters/entities/relics/rival cores, stabilizing or collapsing under pressure, and reseeding the Beyond.

Host Cores can be stable, scarred, overgrown, silent, predatory, collapsed, harvested, or actively reseeding.

The player begins as a small core inside one Host. Later, the player realizes that Host Cores themselves belong to a larger outer ecology.

---

## 04. Core Player Loop

The first playable loop is:

```text
Move -> Observe -> Pulse / Expose -> Absorb / Avoid -> Grow -> Interpret -> Unlock -> Cross
```

The region loop is:

```text
Enter region
  -> Camera reveals mood and route
  -> Guide/orbiter points toward meaningful object
  -> Player moves through obstacles/current/soft walls
  -> Player observes target chemistry
  -> Player chooses verb: pulse, absorb, tune, bind, mend, stabilize
  -> World reacts
  -> Growth, memory, route state, or ecology changes
  -> Gate becomes readable
  -> Player crosses threshold
```

---

## 05. Chemistry as World Interaction

The chemistry workbook is the interaction bible. Chemistry defines how regions behave, nutrients feed growth, materials carry world states, abilities interact with matter, entities feed/mutate/stabilize, orbiters interpret and guide, routes collapse or repair, Hosts metabolize and reseed, and the player identity path forms.

Every playable object should be defined by:

```text
Substance -> State -> Verb -> Reaction -> Risk -> Recovery -> Meaning
```

A nutrient is not just a pickup. A membrane is not just a wall. An entity is not just an enemy. A route is not just a level connection.

## 08. Core Definition System

A Core is not merely the player avatar. It is the player's body, class system, growth tree, chemistry filter, visual identity, story identity, and eventual host-capable seed.

A Core is shaped by nutrients absorbed, entities interacted with, orbiters bonded, abilities used, regions completed, failures survived, repairs performed, relics interpreted, routes chosen, and imbalances corrected or tolerated.

In short:

```text
Core = player body + player build + player history + player worldview
```

## 10. Base Core Abilities

### Pulse

Pulse is outward assertion of self. It exposes, repels, stuns, activates, ruptures fragile matter, and later travels through route structures.

Growth ladder:

```text
Pulse Flicker -> Pulse Burst -> Pressure Pulse -> Resonant Pulse -> Rupture Wave -> Host-Scale Pulse
```

### Absorb

Absorb is taking the world into self. It gathers nutrients and loose matter, but also shapes the core's chemistry and identity.

Growth ladder:

```text
Soft Draw -> Nutrient Pull -> Selective Absorb -> Entity-Safe Draw -> Relic Condensation -> Host-Thread Intake
```

### Stabilize

Stabilize holds coherence under pressure. It resists current, braces in threshold glow, and later anchors route/host systems.

Growth ladder:

```text
Hold -> Brace -> Living Brace -> Route Anchor -> Host Anchor
```

### Guide Scan / Sense

Guide Scan is the core learning to read the world. At first it is guided by the Guide orbiter. Later it becomes a core sense that reads seams, routes, entities, chemistry states, and false guidance.

## 14. Entities and Core Growth

Entities shape the core differently from nutrients. Nutrients are absorbed directly; entities are observed, avoided, weakened, helped, harvested, bonded, freed, corrupted, or protected.

Every entity should have:

```text
food + fear + function + failure state
```

Example:

```text
Spore Grazer
Food: loose Spore Milk
Fear: sharp Pulse bursts
Function: keeps Surface Wake clean
Failure: bloom clog if overfed
Player lesson: not every living thing is enemy
```

## 18. Scene Readability Rules

Every scene should have three readable rings.

| Ring | Purpose | Must Show |
|---|---|---|
| Immediate Play Ring | local gameplay clarity | player, obstacles, nearby nutrients/entities, ability effects |
| Objective Ring | next meaningful action | guide tether, seam/gate, landmark, objective target |
| World Meaning Ring | mood and scale | host anatomy, distant routes, ecology, macro silhouettes |

Important target readability requires at least two cues: motion, glow, shape contrast, guide tether, sound/tone, prompt, entity behavior, or route lines.

Safe and unsafe states should not rely on color alone. Use shape, rhythm, motion, sound, prompt, and Guide behavior.

## 19. Region Construction Grammar

A BLOB region is a living host-space built from reusable spatial organs:

```text
anchor -> boundary -> route -> obstacle -> resource -> entity -> orbiter -> gate -> consequence
```

Every region should answer:

```text
What host function is this?
What movement shape does it use?
What chemistry does it teach?
What entities live here?
What ability does it ask for?
What can go wrong?
What changes after the player acts?
Where does the player go next?
```

### Core Region Parts

| Part | Function |
|---|---|
| Anchor | central readable orientation point |
| Boundary | playable limit that looks like what it does |
| Route | path the player can understand and follow |
| Obstacle | object that asks for a verb |
| Resource | nutrient/material/relic/byproduct to absorb/use/protect |
| Entity | living actor with food/fear/function/failure |
| Orbiter Presence | relationship/interpreter/ability source |
| Gate / Threshold | transition that changes state, not just location |
| Consequence Layer | world remembers what the player did |

## 25. Runtime Architecture

Active rule:

```text
Modes own scene behavior.
Systems own reusable gameplay.
Registries own authored content.
UI displays state only.
Blueprint travels with the build.
```

### Runtime Flow

```text
InputController
  -> Current Mode
  -> Systems update state
  -> GameState stores truth
  -> CameraRig frames world
  -> PromptSystem + HudSystem read state
  -> CanvasRenderer draws scene
```

### Systems

- HostCoreGame: top-level orchestration
- GameState: current truth/state
- InputController: physical input reading
- ControlMap: input-to-action mapping
- CanvasRenderer: drawing
- CameraRig: framing
- LandingMode / ThresholdMode / HubMode / RailMode / CinematicMode / StatusMode: scene behavior
- PlayerCoreSystem: player body state
- CoreGrowthSystem: stage progression
- ChemistrySystem: reactions, risk, chemistry lean
- AbilitySystem: ability execution
- NutrientSystem: nutrients
- EntitySystem: behavior ecology
- OrbiterSystem: bonds/guidance
- GateSystem: crossing logic
- ObjectiveSystem: objective progress
- PromptSystem: current prompt
- HudSystem: HUD display
- StatusPage: menu display
- ValidationReport: data integrity checks

---

## 26. Runtime Update Loop

Each frame should update in this order:

```text
1. SceneLoop calculates delta time.
2. InputController reads input.
3. ControlMap converts input to actions.
4. Current Mode receives actions.
5. PlayerCoreSystem updates movement/body state.
6. AbilitySystem resolves ability use.
7. ChemistrySystem resolves reactions and risks.
8. NutrientSystem updates resources.
9. EntitySystem updates entities.
10. OrbiterSystem updates guidance/bonds.
11. ObjectiveSystem checks progress.
12. GateSystem checks crossing availability.
13. PromptSystem chooses current prompt.
14. CameraRig frames scene.
15. CanvasRenderer draws world.
16. HudSystem draws HUD.
17. Debug overlay draws only if enabled.
```

HUD is last. HUD reads state. HUD does not alter state.

## 27. Registry Philosophy

Registries define authored truth. Systems execute rules.

Bad pattern:

```text

```

