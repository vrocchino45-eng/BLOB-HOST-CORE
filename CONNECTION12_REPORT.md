# CONNECTION12 — local Pulse freshness

November 12, 2026. Mode: convergence / bounded event-validation fix. Serves the protected world–Core slice toward R6. Baseline: CONNECTION11 harness and CONNECTION5 gameplay.

## Trigger and result

RegionalTerritoryExpansion retained the last global Pulse counter while unmounted. A later counter increase was enough to call its local Pulse observation if the player was in range, even when the current canonical input had pulsePressed=false. In a controlled near-site return, a Pulse released elsewhere could therefore be interpreted as a new local exploratory read.

The consumer now requires both a newer counter and pulsePressed=true. Counter gaps are still consumed, so a stale release cannot wait to replay later. A subsequent fresh local release remains available. The initial cursor-seeding behavior and all other input handling are preserved.

This is a reproduced owner-boundary problem, not a claim that the user encountered a visible ghost response in ordinary traversal. Route entry anchors normally begin away from local tissue, which can already consume the stale counter out of range. The browser test deliberately supplies a near-site return to exercise the unsafe boundary.

## Pass contract

Purpose: require a current canonical released-Pulse event before mutating local tissue through the Pulse path.

Allowed scope: one conditional in RegionalTerritoryExpansion, new L01/L02 tests and harness registration/documentation. Locked: the InputSystem mapping and event counter, live region lifecycle owners, local coupling/pressure relief/packet laws, movement/camera, physical current and particle continuity, audio, placement/reserve, targets, material/receipt/credit owners, goals and 3→6→12 grammar. Keep all existing systems. Delete/disable targets: only the unintended counter-only authorization path; no system is removed.

Visual target: no local read/response attributable solely to an old counter gap; preserve existing cues for deliberate action. Feel target: a fresh Pulse still responds normally, with no new button or delay. Rendered perception and physical-controller feel remain separate judgments; this event-validation pass does not retune them.
