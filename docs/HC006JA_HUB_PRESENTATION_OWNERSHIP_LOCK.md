# HC-006JA — Hub Presentation Ownership Lock

## Mode
Presentation convergence / ownership lock.

## Purpose
Make the authored Hub foundation visually and instructionally readable after the Signal Chorus layered interaction completes.

## Allowed scope
- Hub-only Guide, HUD, and tissue instructions
- quieting retained Signal Chorus presentation
- wider route separation
- active/dormant route rhythm distinction
- junction-wide inspection framing

## Forbidden scope
- new route runtime
- Status Page progression
- Vascular or Silt activation
- Comb Threshold or Aperture Fields
- teleport, branch menu, combat, or forced relocation
- Surface Wake or Guide Threshold behavior changes

## Runtime ownership

```text
HubMode
→ HubChamberFoundationSystem
→ GuidePromptSystem / PlaytestHudSystem read Hub state
→ GateSystem retains route availability
→ ObjectiveSystem retains Hub readability completion
```

Retained Signal Chorus and Grave-return states remain durable history, but no longer own visible Hub prompts or dominant geometry.

## Presentation changes
- completed layered-interaction root hidden in Hub ownership
- passive combward-pressure preview hidden in Hub ownership
- old arrival/loop rings hidden
- living Chorus tissue reduced to a low-opacity memory layer
- signal haze and surface reduced
- Hub routes widened spatially
- tight inspection view pulled back and widened

## Lock criteria
- Hub prompt wins over all retained Signal prompts
- center plus three routes visible in one frame
- one active route and two dormant routes remain explicit
- no route activation or target is created
- all earlier first-slice regression tests pass
